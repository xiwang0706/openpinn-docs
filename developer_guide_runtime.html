从新增方法的实施路线开始，再按需要查配置、模型、采样、损失、优化器和恢复契约。 目标不是让名称出现在菜单里，而是让算法经过公共入口运行、可验证且不破坏旧用法。

计划新增方法时，先理解本页的配置和组件职责，再按 新增方法与字段接入步骤 实施； 完成后进入 验证、提交 PR 与版本维护，核对方法测试、兼容性和交付要求。

新增方法：从算法实现到公共入口

本节的交付目标：不是增加一个方法名称，而是交付算法实现、配置接入、可运行示例、回归证据和适用边界。以下是扩展现有代码的路线，不代表所有新方法都能只靠一个插件文件自动安装。

第一步：选对算法所在的层

新方法改变什么优先阅读的代码先明确的契约
特征、激活或网络结构features.py、models.py（按实际类定位）输入/输出维度、可微性、设备与 dtype、参数及检查点兼容
训练点选择与更新sampling.py；采样生命周期SampleBatch、update/sample 时机、随机状态与边界/初值点
残差离散或损失构造formulations.py；问题契约标量/逐点损失形状、名称、自动微分、问题元数据
损失加权及其自适应losses.py；损失数据流compose/adapt、权重更新时机、内部状态和恢复
优化步骤与阶段切换optimizers.py；训练循环closure、梯度清零、重复求值、累计步数、状态保存

原则：先复用现有接口，算法实现放对应公共模块，方法变体只描述配置。确实需要修改 Trainer 协议时，先列出所有消费者和迁移方案；不能为了让一个算法运行而悄悄改变其他方法的训练语义。

第二步：沿现有方法走通接入链

以已有的 adaptive_sampling/residual_adaptive 为阅读样例，不要求重新实现它：

  1. src/openpinn/sampling.py：阅读 ResidualAdaptiveSampler，确定算法实际执行的位置。
  2. src/openpinn/methods/adaptive_sampling/residual_adaptive.py：VARIANT 描述变体；_options 把采样选项放入 sampling.options，把 resample_every 放入 training。
  3. src/openpinn/method_options.py：参数类型、范围、默认值与用户说明；未知参数必须被拒绝。
  4. src/openpinn/method_registry.py 及家族 __init__.py：变体可发现性、名称和配置补丁。新增家族还需定义 slot 与方法顺序。
  5. src/openpinn/experiment.py：_residual_adaptive_sampler_factory 创建实际对象；检查配置白名单及工厂传参。loss composer 是独立分支，不适用“所有组件都注册同一表”的假设。
  6. tests/methods/adaptive_sampling/test_residual_adaptive_variant.py：通过公开 family / variant 入口短跑；不要只测试类能实例化。

第三步：区分三种变化的接入范围

  • 增加已有方法的参数：schema → option_patch → 工厂 → 算法行为 → 参数测试；不需要凭空新增家族。
  • 增加已有家族的变体：新变体 spec、家族导出/注册、schema、组件创建及变体测试；声明和同族其他方法的区别。
  • 增加全新家族：除上述步骤，还需兼容性、slot、排序和组合规则；明确哪些组合应拒绝。对应配置、方法文档与网页元数据同步。

实现清单见已有扩展细则；底层运行细节按需阅读方法配置与组件创建，不必先通读函数附录。

第四步：什么叫“方法接入完成”

  1. 合法、非法、极值参数均有测试；默认值有依据，参数变化能改变目标行为，而非只改变输出文本。
  2. 公开 API 有最小运行样例；如承诺支持 CLI/配置器，也实际检查相应入口。不能把只在脚本中支持的能力写成网页已支持。
  3. 有组合冲突、老配置/旧调用回归；若新增内部状态，检查保存与恢复，明确旧 checkpoint 的处理。
  4. 文档说明适用问题、单位、计算代价、限制与失败案例；可复现输入无需个人电脑文件。
  5. 只做短跑时写“链路验证”；声称更准/更快时提供同问题、预算、硬件、评估点和多种子比较，不能只比较训练 loss。

可先执行的现有回归

python -m pytest -q tests/unit/test_method_registry.py tests/unit/test_method_composition.py
python -m pytest -q tests/methods/adaptive_sampling/test_residual_adaptive_variant.py

这些命令验证现有接入链，不会自动证明你的新算法正确。按新组件补专门测试，并依据变更类型验收表选择后续检查，再准备PR 证据。

05 · 方法配置与计算组件：从选择方法到创建对象

5.1 方法配置注册表（MethodRegistry）

记录可选方法、变体和对应配置规则，把用户选择转为配置；它本身不执行采样或训练。MethodVariantSpec 定义 name、title、component_file、variant_file、description、aliases、compatible_with、requires_checkpoint、default_patch、option_patch、finalize_config。MethodSpec 表示家族与已选变体信息。各变体一般只生成配置补丁，算法体在公共模块中。

default_method_registry 注册普通 PINN + 十个改进家族；resolve 处理规范名称/别名/默认变体。apply_method 先用 problem_family 校验兼容声明，再合并默认补丁、校验用户选项、执行选项补丁与 finalizer，最后写 resolved=true。

5.2 method_options：前后端共享参数来源

METHOD_PARAMETER_SCHEMAS 描述每个变体的字段类型、默认值、范围、中文解释与影响；validate_method_options 拒绝未知键并调用 _validated_value。前端 payload 从该目录得到参数，不能只增加一个 HTML 输入框就认为后端支持该参数。

方法占用 slot
modified_mlpmodel_architecture
adaptive_activation / fourier / hard_boundary分别 activation / feature / constraint
adaptive_weights / adaptive_sampling分别 loss_weighting / sampling
adam_lbfgs / transfer分别 optimizer / initialization
time_windowsampling + time_schedule
domain_decompositionmodel_architecture + feature + constraint + formulation

validate_method_stack 拒绝重复家族、slot 冲突与 baseline 混用，随后按 METHOD_ORDER 排序。顺序不是用户勾选顺序；新增方法必须明确 slot 与排序，否则组合会有覆盖歧义。

5.3 计算组件注册表（ComponentRegistry）

记录组件名称与创建函数的对应关系，根据配置创建实际参与计算的对象。类别是 problem、model、feature、constraint、formulation、sampler、optimizer。register 检查名称/别名冲突；canonical_name 统一名称；factory 取工厂；create 调工厂并验证返回类型或 Protocol。copy 创建独立注册映射。注册器不是进程级全局可变插件中心。

default_component_registry 在 experiment.py 中绑定内置工厂。高级用户可传自定义注册器给 Experiment；短 API solve 本身不提供 registry 参数。loss composer 当前经 _loss_composer 分支创建，不属于 ComponentRegistry 的七个类别；扩展损失时不要误认为只注册一个名字就够。

兼容报告只检查声明结构。check_method_compatibility 返回 applicable / conditional / incompatible，不承诺数值收敛或对任意自定义 PDE 都适用；transfer 的结构匹配、域分解的材料元数据还需实际验证。

04 · 短 API、CLI 与配置解析的实际顺序

4.1 op.solve 的主调用链

  1. solve(problem,...) 进入 try 区，调用 build_config。
  2. build_config 拒绝单方法与方法栈混用；经 coerce_method_selection/select_method 与 validate_method_stack 产生有序 selections。
  3. _problem_defaults 选择内置问题默认配置。若传入 PDEProblem，使用 user_problem 占位名，并由 _default_problem_loss_weights 生成损失键。
  4. 合并用户问题、模型、采样、training 与 overrides。steps 由短 API 顶层参数锁定。
  5. 按固定方法顺序调用 apply_method。若多方法，记录 methods 列表并生成组合描述。
  6. default_component_registry() 创建独立组件注册器；用户 PDEProblem 注册为返回该实例的 user_problem factory。
  7. 构造 Experiment(config, registry=registry) 并执行 run(output_dir=...)。
  8. 可选 write_result_figures，写成功限制说明，刷新 manifest，返回 result。
  9. 异常路径经 _failure_target 选择不覆盖已有数据的目录，write_failure_artifacts 写失败产物，然后重新抛出原异常。

4.2 配置覆盖优先级

内置/用户问题默认值
  → problem_options / model / sampling / training
  → overrides（随后再次固定 training.steps）
  → 方法 default_patch
  → 校验后的方法选项生成 option_patch
  → finalize_config（例如分配 Adam/L-BFGS 步数）
  → 方法执行记录
“overrides”名称不意味着它最终压过方法补丁。当前方法在其后应用，方法控制的组件字段仍可能覆盖前面的设置。排查时看最终 config.yaml 或 build_config 返回值，而不是只看调用参数。

4.3 solve_config 与 CLI

load_config 对 Mapping 做深拷贝；路径按 JSON 后缀解析 JSON，否则用 yaml.safe_load。solve_config 接受紧凑 schema 2，读取问题名或 factory，解析单方法、training、output，拒绝未支持顶层键，再调用 solve。结果仍保存 schema 1。

load_problem_factory 支持 module:function 或 relative/file.py:function；文件路径相对于配置文件目录（传 Mapping 时按指定基准/当前目录）。使用 importlib 导入会执行 Python 顶层代码，不能把名称中的 “safely” 注释解释为安全沙箱，只能加载可信工厂。

cli.main 负责 argparse 分发：list-methods 列 registry，show-config 调 build_config，run 无 --config 时调 solve，有 --config 时调 solve_config；后一分支只额外传 output_dir 与 steps。不要为尚未实现的 CLI 覆盖行为写使用承诺。

09 · 模型、特征变换与硬约束

PINNModel.forward(coordinates)
  → feature_transform(coordinates)
  → network(features)
  → output_transform(coordinates, raw_output)
  → prediction

models.py 管理 MLP、ModifiedMLP、AdaptiveTanh、PINNModel、DomainDecompositionPINN 与末端层冻结。features.py 中 IdentityFeature 不改变坐标，FourierFeatures 生成频率映射并可拼接原始输入；constraints.py 中 IdentityOutput 直接放行，HardConstraint 用 extension + distance×raw 把已知条件嵌入输出。

组装时的函数关系

_model 通过注册工厂选择网络；MLP 工厂调用 _feature 和 _constraint，利用特征输出维度构造网络；_model_output_dimension 对输出与问题字段数进行检查。ModifiedMLP 是不同结构，不应把其 checkpoint 与普通 MLP 互换。

硬边界的实际限制

_hard_transform 的 Interval 分支取第一个 Dirichlet 条件，在左右端点评估目标并作线性 extension，distance 为 (x−lower)(upper−x)。因此多个互不相同的独立 BC 并不会自动被这个函数综合成正确 extension。时空分支有特定一维初值形式，不能直接推广至任意二维动态问题。

前端对自定义硬边界更保守：只允许一维、左右等值 Dirichlet。新增支持时应同时修改生成器和后端条件构造，并加“不调用 exact_solution 构造训练约束”的回归测试。准确解只能做验证，不能泄漏到训练。

冻结与迁移

freeze_all_but_last_linear_layers 通过线性层顺序控制哪些参数可训练。_mlp_model_factory 等读取 trainable_last_linear_layers；Experiment.run 使用 strict model.load_state_dict 加载模型权重。检查输入维度、特征维度、输出数、层宽和参数命名，不能只比较问题名称。

10 · 采样器生命周期和状态

SampleBatch 保存 interior、boundary、initial 以及可选 interior_weights；其 to 负责设备/类型转换，as_dict 用于状态保存。SamplerProtocol 要求 sample/state_dict/load_state_dict；update 与 diagnostics 通过能力检查调用，不是每个采样器都必须实现。

组件主要关系注意点
UniformSamplersample → problem.domain 的内部、边界与初值采样独立随机生成器；reset/state/load 影响可复现性
ResidualAdaptiveSamplerupdate 用模型残差评价候选点；sample 返回更新后的批候选池、幂、均匀混合与 seed 必须记录
AdaptiveMovementSampler_scores → update → 移动/调整采样点残差型与梯度型的导数计算成本不同
ImportanceSamplingSampler候选概率采样 + interior_weights权重需一路传到 StrongFormulation，不能只改点分布
TimeWindowSamplercurrent_window_end/update/sample 逐步扩大时间覆盖窗口状态与底层随机状态应一起保存

重采样的真实时机

Trainer.fit 中仅在没有 active batch 或 steps_completed % resample_every == 0 时重取样本；已有步数>0 且 sampler.update 可调用才执行 update。随后固定这一批交给本次 optimizer.step。L-BFGS 多次 closure 必须使用同一批，不能在 closure 内每次重新采样。

改变 fit 的 resample_every 会清空 active batch。采样策略的状态、active batch 和重采样相位都参与完整 checkpoint，以便恢复不改变采样序列。新采样器至少验证样本数、域内合法性、可复现性、状态恢复和 diagnostics 的有限值。

11 · 损失组合与自适应权重的数据流

LossComposer 接收 name→scalar Tensor，按权重及 reduction 合并。MagnitudePowerLossComposer 在合并前作具名幂根变换；AdaptiveLossComposer、PointwiseAdaptiveLossComposer、UncertaintyLossComposer、ReLoBRaLoLossComposer 提供不同适应策略。算法实现集中在 losses.py，不在方法入口脚本里各复制一份。

Trainer._loss_payload(batch)
  ├─普通路径：formulation.loss_terms → composer(terms)
  └─requires_pointwise_terms：pointwise_loss_terms
       → 每项均值得到 scalar terms（记录用）
       → compose_pointwise(pointwise terms)（优化用）
optimizer.step(closure) 更新模型
  → composer.adapt(latest pointwise 或 scalar terms)
  → 记录当前权重、各项损失与 total

逐点权重需要 formulation 的 pointwise_loss_terms；只有标量 loss_terms 的自定义 formulation 不够。模型优化器与自适应权重的更新并非“把所有 nn.Module 参数随便扔入同一个 Adam”；当前 composer 自有 adapt 及其训练状态，扩展时遵循该接口。

TrainingHistory 的 total 在更新权重后按 weighted_terms 汇总，不能保证与 optimizer.step 返回的同一步 closure 目标逐位相同，尤其不同变体含正则或非线性变换时更应谨慎。不同方法的 total 不宜直接作为最终精度排序依据。

新增损失项时的检查矩阵

  • 残差返回键是否出现在 metadata.residual_names 与默认权重中。
  • 条件同名后缀是否与 composer 期待键一致。
  • pointwise 项点数是否随重采样变化，而 composer 是否支持。
  • state_dict 是否包含必要的历史统计、随机状态和独立优化器状态。
  • 评价仍应使用原始残差/参考误差，不用变换后的训练目标替代。

12 · Trainer.fit 与优化器 closure 的逐步时序

  1. 构造 Trainer：PDEProblem 自动包装为 StrongFormulation；检查 FormulationProtocol/SamplerProtocol；推断或设置 device/dtype。
  2. loss_composer 与 loss_weights 不能同时传。优化器若已是 OptimizerAdapter 则复用，否则由 make_optimizer 建立。
  3. fit 校验 steps/epochs 一致性、重采样间隔和 sampler。
  4. 按采样周期 update/sample，保存 active batch。
  5. 建立局部 closure，调用 _loss_payload，并把 latest_terms / latest_pointwise_terms 留给适应和记录。
  6. optimizer.step：AdamAdapter 的父实现通过 _backward_closure 执行 zero_grad、求 scalar loss、backward，累计 closure_calls，然后底层 step。
  7. LBFGSAdapter.step 交给 torch.optim.LBFGS，多次调用同一 closure；StagedOptimizerAdapter 则按阶段计划切换 adapter。
  8. 如 composer.adapt 存在则执行，累计 steps_completed。
  9. 记录 step、elapsed_seconds、具名损失、total、权重和可选 optimizer_stage。
  10. 调用可选 callback；满足打印规则时输出日志。
  11. 更新累计 elapsed_seconds，返回累计 TrainingHistory。

关键不变量

  • 优化器闭包必须返回标量 Tensor，否则立即报错。
  • 不要在单步 L-BFGS 重复闭包里改变随机采样或自适应权重。
  • 日志间隔不改变优化步数和采样间隔。
  • fit 是累计追加历史，不是每次自动从头开始。
  • Trainer 只进行训练与状态管理，不为每步自动写完整实验目录。

训练外的方法

evaluate_loss 接收现有 batch 或生成新 batch 并返回具名数值；predict 在 no_grad 下预测，只适合输出值，不适合需要坐标导数的残差评价。Experiment 的残差评价重新打开坐标梯度，不通过 predict。

13 · Experiment.run：组装、评价和落盘

Experiment 构造阶段读取配置并执行 _validate_config。配置 schema 1，method/methods 若存在必须 resolved=true；未知组件或未知字段应报错，不隐式回退。default_component_registry 中的工厂负责从各配置段构造对象。

随机种子 / device / dtype
 → _problem → _model → 可选 initial_checkpoint（仅模型）
 → _formulation → _sampler → _loss_composer → _optimizer
 → Trainer(...)
 → 检查输出目录非空冲突 → write_config
 → fit（计时范围）
 → _evaluation_coordinates → model → evaluate_residual
 → 原始残差 / 参考解 / 逐场误差
 → _condition_metrics / 界面指标 / 双隧道物理输出
 → sampler / optimizer diagnostics
 → _assert_finite（历史、指标、预测）
 → write_metrics/history/predictions/ledger/status/checkpoint/manifest
 → ExperimentResult

ExperimentResult 契约

包含 metrics、history、predictions、output_dir、model、compute_ledger；支持键索引及 as_dict。model 保留在内存以支持独立参考点再预测；磁盘 checkpoint 不是同一个 Python 对象。新增结果字段需要同步公共契约测试。

评估坐标

_evaluation_coordinates 针对一维使用线性网格，二维使用包围盒网格再 contains 过滤，时空域叠加指定时间切片。默认二维 evaluation.points 整数会转换到网格侧长，不表示强制得到相同数量的域内点；带孔过滤后样本数会减少。新增 geometry 必须同步该函数的类型支持，否则“可以训练”不保证“可以评估”。

有限值与失败范围

_assert_finite 在保存最终结果前检查历史、指标和预测；这是输出验证，不是逐步稳定性证明。api.solve 捕获异常并写失败产物。直接调用 Experiment 的异常路径不一定具有完全相同的高层 failure_notes/标准图行为；不要在说明中混称。

14 · 指标、参考场、图像与文件契约

14.1 metrics.py

rmse、mean_absolute_error、max_absolute_error、relative_l2_error、r2_score 接收张量或数组并返回 Python float。relative_l2_error 使用参考范数的 eps 下限；r2_score 对几乎常数参考采用有限值约定（足够小残差为 1，否则 0）。不存在自动面积权重。维护时禁止通过裁剪预测或丢弃大误差点来改善指标。

14.2 外部参考链

evaluate_reference_csv(result,path,columns,scales,...)
 → _read_csv：解析表头/序号/分隔符/重复坐标
 → 校验模型输入数、输出分量、换算系数与固定时间
 → 坐标换算 → 可选 problem.domain.contains
 → result.model 在 reference 坐标分批 inference
 → 预测与参考分别转换到同一报告单位
 → 指标 + reference_predictions.csv + reference_comparison.svg
 → result.metrics 添加 external_reference_* → 更新 metrics 与 manifest

coordinate_columns 按输入顺序；固定时间时把它追加为最后一维，coordinate_scales 仍含时间系数。value_scale 与 prediction_scale 是独立转换。传入 problem 才进行域内检查；不能把省略 problem 的调用宣称也验证了域外点。分批预测后恢复模型原 training 状态。

reference_metrics.json 记录源 SHA-256、列与单位、去重信息、evaluation_only=true、interpolation=false、metric_weighting=uniform_per_distinct_sample_point。参考场不参与 Trainer。文件更新后重新写 manifest，避免旧校验清单。

14.3 artifacts.py

ArtifactWriter 对配置、JSON、CSV、NPZ、checkpoint 统一保存；_jsonable 处理 Path、Tensor、NumPy 等。write_manifest 记录文件大小与哈希。write_result_figures 根据问题/数据生成图，双隧道由 _write_tunnel_result_figures 专门处理。

双隧道显示层中的 _nearest_fill_missing、_smooth_grid_rgb、_png_data_uri 与 _grid_field_panel 用于构造平滑栅格图并嵌入 SVG；这些只服务显示。不得把填补孔洞/显示插值后的数组当作真实域内预测写回 NPZ 或交给指标函数。诊断图与训练 loss 分离。

14.4 输出验收

基本文件：config.yaml、status.json、metrics.json、history.csv、predictions.npz、compute_ledger.json、checkpoint.pt、manifest.json（保存 checkpoint 开关影响直接底层调用）。solve 默认额外写图和 failure_notes；部分方法有 sampling/optimizer diagnostics，独立参考对比有 reference_*。completed 与 finite_outputs 不构成精度认证，accuracy_claim=false 保留这一边界。

15 · 完整断点恢复与迁移的边界

路径恢复内容用途
Experiment 的 training.initial_checkpoint / transferstrict 加载 model 权重；记录源路径和 SHA-256新任务初始化/微调；新优化器、采样和历史
Trainer.load / load_state_dict模型、优化器、composer、计数、历史、随机状态、采样器、active batch、resample_every相同组件配置下继续训练

最小恢复示例

from pathlib import Path
import torch
import openpinn as op

def make_trainer(seed):
    torch.manual_seed(seed)
    problem = op.make_poisson_problem()
    model = op.PINNModel(op.MLP(1, 1, hidden_layers=(8, 8)))
    sampler = op.UniformSampler(problem, interior=12, boundary=4, seed=seed)
    return op.Trainer(model, problem, sampler, optimizer="adam", lr=1e-3)

first = make_trainer(7)
first.fit(steps=2, resample_every=3)
checkpoint = first.save(Path("resume_demo/checkpoint.pt"))
continued = make_trainer(99)
continued.load(checkpoint, map_location="cpu")
continued.fit(steps=2, resample_every=3)
assert continued.steps_completed == 4
print("完整训练状态已恢复并继续")

torch.load 使用 weights_only=True，但仍应只接受可信且资源规模合理的文件。恢复前需要重建相同模型、formulation、sampler、composer 和优化器，不可把不同配置恢复成功当作默认保证。回归测试排除 elapsed_seconds 比较数值一致性；跨硬件/版本的逐位一致性不在当前测试结论内。
