修复与细节改进：从一个失败案例开始

不是每项贡献都涉及数值算法。报错信息、默认值说明、复制按钮、文件解析、圆孔编号、坐标换算、文档导航都需要维护。先判断变更属于表现层还是行为层，再决定验证范围。

定位顺序：复现 → 回归 → 最小修复 → 相邻行为

  1. 复现：从干净构建的页面或最小脚本开始，记录输入、点击/拖动顺序、期望与实际结果；保留原有效状态以便比较。
  2. 定位源：网页结构查 docs/_ext/openpinn_method_catalog.py，交互查 docs/_static/method_configurator.js，样式查同目录 CSS；不是编辑 docs/_build/html 或旧 dist 副本。
  3. 留回归：能自动化时先增加在修复前失败的断言；不能自动化的视觉问题记录前后截图、窗口尺寸、缩放与键盘步骤，不谎称截图测试能覆盖数值行为。
  4. 修复：只改根因及必要调用点，保留有效输入、错误反馈和历史接口。不要用捕获所有异常并返回默认值掩盖问题。
  5. 验证：原案例通过，并测试相邻对象不变、切换/重置/重复导入、无效值拒绝。参数语义变化时还要运行生成脚本。

按变更内容选择范围

改动应验证不应做的事
文案、目录、图示、CSS构建、链接、可读性、窄屏/键盘与已有交互；图示和实现一致无故修改求解器，或宣称数值精度改进
输入框、默认值、错误提示input/change 事件、空值/NaN/极值、状态与生成代码只更改标签或 DOM.value，不检查实际事件
导入、顶点/圆孔编辑、条件编号解析、状态保留、编号、selector、法向、预览、生成对象与短跑用截图外观相似替代几何/边界契约检查
指标或输出文件已知输入输出、原始数组和文件字段契约、旧消费者裁剪预测或丢弃误差点来美化指标

跟做已有案例，学习怎么找改动点

阅读DXF 圆孔贯穿案例：它给出输入、源码文件、修改后必须变化/不变的部分和精确测试命令。先复现现有行为，再把同样的方法用于自己的问题；不要为了练习重新添加已经存在的圆孔功能。

改字段时重点看前端函数契约和参数到训练代码的对应关系。SVG 只是预览，真正的交接产物是生成的 Python；复制到编辑器的旧脚本不会自动更新。

提交前最少留下什么

一个最小复现、一段根因说明、一个针对性回归（或说明无法自动化的人工步骤）、影响范围及截图/日志。较大重构先与维护者讨论；修复和纯格式整理尽量分开，便于审阅和回退。完成后进入提交与审阅流程。

16 · 网页配置器：从 Sphinx 到 Python 代码

16.1 不是 Blockly 运行时

当前主配置器是 Sphinx 扩展生成 HTML/payload，再由原生 JavaScript 管理表单、SVG 与 Python 文本。不能因为历史讨论提过 Blockly 就把现有实现写成 Blockly 集成；维护应查看实际资源和函数。主文件为 docs/_ext/openpinn_method_catalog.py 与 docs/_static/method_configurator.js，样式为同名 CSS。

代码面板通过 CSS Grid 跨整行。放大时把同一个 code-pane 节点移入原生 dialog，关闭事件再恢复到占位注释之后，不复制代码 DOM，避免两个预览失去同步。下载从当前 code.textContent 创建 UTF-8 Blob；updateCode 同步控制复制和下载的禁用状态。保留 white-space: pre 与横向滚动，不提供自动换行。回归测试为 tests/js/configurator_code_pane.test.cjs；DOM 测试不能代替浏览器中的模态焦点约束、Esc 默认行为及响应式布局验收。

展开原始细化步骤 / 调用说明
Sphinx 扩展读取 registry / 参数 schema / 方法文档元数据
 → 渲染 data-role HTML 字段 + JSON payload
 → startConfigurator(root,payload)
 → 当前问题、selected 方法、参数缓存、几何/边界状态
 → renderMethodList + renderParameters + toggleCustomFields
 → renderCustomPreview（SVG 建模示意）
 → updateCode
      ├─generatedProblemLines（几何 / PDE / BC / IC）
      ├─generatedMethodLines（op.method 列表）
      └─op.solve 与可选 evaluate_reference_csv
 → 用户复制 → Python 独立运行

16.2 状态与渲染分工

函数群作用联动要求
currentProblem / currentFamilies / isCompatible读取选中问题与允许的方法切换维度/类型后重新检查兼容性
ensureValues / createInput / readParameter参数缓存、控件生成与类型解析不得仅更新显示值而漏掉实际参数
findConflict / generatedMethodLines前端 slot 冲突提示与方法代码后端仍需 validate_method_stack
readCustomSettings / readCustomTerms / readCustomBoundaries收敛表单值成当前问题设置数值有限、维度与项兼容、域有效
customFormulaLatex / renderCustomPreview公式与 SVG 示意必须明确非训练结果；不能宣称按任意 PDE 求解
generatedProblemLines生成输入坐标、残差、域对象和 BC/ICexactAvailable/hardBoundaryCompatible 的条件不可绕过
updateCode / renderAll校验通用字段并统一刷新代码/显示错误时不能留下可误复制的旧有效代码

事件中 input 与 change 并用。部分普通参数逐键刷新，而顶点、圆孔尺寸等按提交字段更新；不要在测试中只改 element.value 而不派发对应事件，就认定同步有效。更新 HTML data-role 必须同步 JS 查询，否则 null.addEventListener 会在初始化时直接中断整页。

16.2.1 关键函数维护卡：输入、输出、状态与失败语义

下列函数位于 startConfigurator 闭包内，并非可从其他脚本直接调用的公共 API。它们共享表单节点和状态；函数名相同不代表无副作用。返回值为 undefined 的过程函数不能当作返回新几何的纯函数。

函数 / 输入→返回读取 / 修改调用时机与后续失败与维护约束
setPolygonData(polygon, keepOriginal) → undefined输入为已校验的 outer/holes/bounds/sourceName，可能附 circularHoles；写当前几何、范围字段和提示。keepOriginal 为假时另存重置快照并重置边界状态导入完成或编辑提交；刷新编辑器、边界行、SVG，最后 updateCode先调用 importedGeometryInfo，解析孔越界/相交在提交前抛错；它本身不是任意输入的完整 normalize/validate 入口。不要删除调用方 validatePolygon
applyPolygonRings(rings) → undefinedrings[0] 外环，其余孔；读取旧几何的来源、图像与 DXF 元数据。validatePolygon 后对原本已标记圆孔重新拟圆顶点、边长、变换与圆孔参数编辑；经 setPolygonData(validated, true) 提交校验异常交给事件处理器。未再满足拟圆条件的孔可失去 circle metadata；不能只更新点列而保留错误圆心/半径
reconcilePolygonBoundaryState(reset) → undefined按当前环、边数量重建 state；reset=false 按旧 ringIndex/edgeIndex 复用条件，缺项用默认值setPolygonData 及边界定义读取前；影响 polygonBoundaryDefinitions这是索引保留，不是空间匹配算法！交换两孔次序或插入边时，不会自动理解旧边对应谁。更改拓扑必须设计显式映射或明确重置并测试
importedGeometryInfo(polygon) → {analytic, lower, upper, note}读取 outer、holes、circularHoles；不重排顶点或孔几何提交前与 readCustomSettings；决定训练用解析矩形圆孔还是 Polygon解析路径严格验证圆孔尺寸、外框接触与孔相交；普通多边形落入近似分支，不强行拟合矩形
readCustomSettings() → settings读取问题、维度、几何参数、PDE 项及边界；polygon 引用当前对象，不是独立深拷贝。读取多边形边界时可能协调边界 state公式/预览/代码生成读取统一设置非法范围、维度、非有限数、缺几何等抛错。不要把返回对象视为可随意修改的隔离快照
generatedProblemLines() → string[]读取当前设置与所选方法；返回域、残差、条件、PROBLEM 等 Python 行updateCode 拼装完整脚本时调用；内置问题仅返回其简称赋值不执行 Python、不训练；自定义硬边界不兼容等情况抛错，由 updateCode 展示错误。测试必须实际编译/运行输出
updateCode() → undefined读取通用参数、方法与自定义设置；写 code.textContent、状态消息和复制/下载按钮输入、方法变化、几何提交后统一刷新内部捕获错误，把输出替换为修正提示并禁用复制/下载。不能只保留旧有效脚本而不标明状态

关联测试：tests/js/imported_analytic_geometry.test.cjs 检查几何编辑、条件保留和生成文本；tests/smoke/test_imported_analytic_codegen.py 执行生成的问题；tests/js/configurator_code_pane.test.cjs 检查面板移动、复制、下载与错误禁用。圆孔参数修改失败时，事件处理器显示错误并用旧状态重绘输入框；这属于“拒绝新修改、保留原几何”，不同于 updateCode 对无效通用参数的“禁用导出”。验收时必须区分两种结果。

16.3 与其他设计页区分

仓库还包含 problem_designer.js、visual_problem_designer.js 及对应 rst；它们不是当前配置器主链的替代入口。修改当前功能前确认被加载的页面/脚本，避免只修一个不再作为主入口的预览页。

16.4 自定义参数从界面到训练的对应关系

物理编辑器的主操作顺序为“模板/场单位 → 导数按钮与公式预览 → 当前参数”；参数库、材料组、文件操作及每行高级信息默认折叠。默认参数列是名称/符号/值/单位，折叠不等于删除 id、说明或来源；这些字段仍应完整进入 spec 和导出。新自定义参数允许留空 id 并生成不冲突的 custom.<symbol> 标识。导数按钮随当前场符号更新，无选区时插入场导数，有选区时包裹选中表达式；维度与静动态禁用规则必须与解析器一致，不新增二阶时间导数支持。切换主配置的维度/类型不得隐式替换已有公式和参数。

场变量改名在 change 提交时按完整符号替换公式，不能误改 exp 等函数名或包含同一字母的参数。有等号时，公式预览保留等号两侧，训练 AST 仍为左侧减右侧。配置器页首的可点击流程图由 docs/_ext/configurator_flow.py 生成，入口是 openpinn-configurator-guide 指令；节点跳往真实说明页并在新标签打开以保留配置。修改路由需运行 tests/js/configurator_guide.test.cjs，不要只检查 SVG 外观。

2026-10-15：物理参数与安全公式链路。

src/openpinn/physics_catalog.json 是单位、参数定义与演示模板的数据源；physics.py 提供目录/规格校验及 make_physics_residual。Sphinx 扩展把目录嵌入页面，physics_editor.js 解析限定公式语法、检查量纲，readCustomSettings 取得完整 spec，generatedProblemLines 内嵌为 PHYSICS_SPEC 并创建可微残差。不要对输入使用 eval 或执行导入代码。

参数定义不等于材料值，物理参数不属于学习率等方法参数注册表。spec 坐标/场/参数按选定单位输入，残差内转 SI，每次坐标求导须应用链式换算；x/y 单位相同。只支持标量一维/二维、至多二阶总导数及一阶时间导数；边界仍用原始显示单位，完整多场 Biot 和通量边界没有自动组装。扩展时同时更新 JS/Python 校验与 tests/unit/test_physics.py、tests/js/physics_editor.test.cjs、tests/js/physics_codegen.test.cjs、tests/smoke/test_physics_codegen.py。协作格式与验收计划见 catalog/README.md 和 catalog/ACCEPTANCE.md。

输入/状态读取与处理代码生成落点后端责任

当前链路的交接点是生成的 Python 文本，不是网页向训练进程推送实时状态。修改页面后需重新复制脚本；修改已运行脚本也不会反向更新网页。开发者应把生成脚本视为一个需要语法检查和短跑验收的产物，而非只测试预览外观。

16.5 自定义功能的联动验收矩阵（维护要求）

以下是今后改动应执行的验收要求，不表示每次文档构建已经执行全部浏览器和数值测试。使用者说明书第 06 章的三个操作案例可作为场景基准。

场景动作与正向断言负向/回退断言
一维混合或不等值端点条件单独改右端 c；生成的 RIGHT_BOUNDARY_VALUE 改变、LEFT 不变；改类型后条件类与法向一起匹配左右不等值时硬边界方法不应生成看似有效的代码；Robin α=β=0 应报错
二维多边形拖动顶点、提交边长；提交后 POLYGON_VERTICES 与预览坐标一致，边号与条件 selector 对应自交/退化几何应拒绝或回退；不能让旧代码伪装为新几何结果
两个圆孔分别改圆心、r、D；D=2r，HOLE_N_* 更新，另一孔不变，整环条件保留半径非正、孔相交或越界时不能静默接受；未识别圆形的环不得套用圆孔参数
PDE 与时间逐项改系数、增加/删除项；公式与残差同步；动态域时间列在末尾静态不能接受时间导数，一维不能接受 y 导数；u_tt 可选不等于完整支持二阶初值问题
独立执行保存生成文本，Python 语法通过，再以小预算执行并检查产物只修改 DOM 的 value 不派发 input/change、只截图或仅检查文本非空，均不足以证明同步

建议测试顺序：纯几何/解析器单元测试 → 表单事件与生成文本联动 → 生成脚本语法与短跑 → 真实浏览器缩放、拖拽和回退 → 有独立参考的收敛验证。不同层次分别记录结果，不能用短跑替代精度验证。

17 · 图片识别、DXF 解析与几何编辑管线

17.1 图片

file input → loadPolygonImage(FileReader + Image)
 → processPolygonImage：缩放 / canvas 像素 / 当前识别设置
 → OpenPINNImageTrace.imageDataToPolygon
      automaticSegmentation 或 luminance threshold
      → largestComponent → boundaryLoops
      → 面积过滤 → simplifyClosed → 外环与孔洞
      → 坐标映射 → analyticShapeCandidates / curveEvidence
 → 几何模式选择 → validatePolygon 或曲线参数
 → setPolygonData / 编辑器 / 边界 / SVG / 代码

自动分色比较边界背景与主要填充色，透明度也参与；不是 OCR 或深度学习识图，也不是任意照片分割器。算法保留最大连通分量，微小环有最小面积阈值（max(4, width×height×0.0001)），因此提高分辨率并不能保证任意小孔一定保留。自动曲线判断在存在孔洞时不走整域样条替换。

17.2 DXF

DXF 文件文本 + unit scale
 → OpenPINNDxfImport.parseDetailed
 → ASCII group code/value 解析与平面检查
 → closed rings / open paths
 → 开放 LINE/ARC/SPLINE 等按端点拼接闭环
 → 外环/孔洞分类 → circularRing 检查孔洞
 → outer / holes / unitsCode / circularHoles 等元数据
 → validatePolygon → setPolygonData
 → polygonBoundaryDefinitions：整圆孔一行，其余逐边

 → generatedProblemLines：解析 RectangleWithCircularHoles 或 Polygon 近似点列

DXF 解析器位于 dxf_geometry_import.js，通过 UMD 方式同时供浏览器和 Node 测试使用。circularRing 当前要求至少 24 点、近似等宽高的包围盒、拟合径向误差在半径约 0.003 的容差内；中心/半径有有效位数规范化。该阈值是实现选择，不是普遍几何真理，变更时必须有“真圆、椭圆、噪声近圆、小边数多边形”回归样本。

17.3 状态一致性

customPolygonData 管理 outer、holes、circularHoles；clonePolygonData 必须保留附加元数据。customPolygonBoundaryState 与顶点/边序关联；reconcilePolygonBoundaryState 在几何变化时协调条件。polygonBoundaryDefinitions 对 circle 孔用 polygonRing 标识，对普通边用 polygonEdge。

图形渲染的过滤条件必须同时接受 polygonEdge 和 polygonRing，否则条件列表正确但圆孔边界/标识在图里缺失。当前图中孔洞 N、直径 D 与选中虚线由 renderCustomPreview 生成；索引来自 holes 的同一顺序，不另按 x 坐标排序。

17.4 编辑函数

OpenPINNImageTrace 的 transformRings、setEdgeLength、setInteriorAngle、edgeMeasurements 承担纯几何运算；GUI 的 applyPolygonRings 再校验并更新状态。拖动应通过 SVG 视图坐标换算而非直接拿屏幕像素当物理坐标；clientPointToViewBox 处理尺寸/留白映射，缩放浏览器后需测试。

圆心/半径/直径字段的 change 事件根据 D/2 同步半径、重采样环，再驱动预览与 updateCode。测试至少覆盖孔洞 1 修改而孔洞 2 不变、边界条件不丢、空值/非正半径拒绝、孔洞越界回退、重新导入编号正确。

19 · 新增方法、几何和前端字段的闭环

19.1 新方法变体

  1. 在对应公共组件实现算法，满足原接口；优先避免改 Trainer 主循环。
  2. 在 methods/<family>/ 新建文件，定义 VARIANT=MethodVariantSpec，提供 default_patch、option_patch、必要 finalizer。
  3. 更新该家族 __init__ 导出及 method_registry 的注册；新增家族还需 METHOD_SLOTS、METHOD_ORDER。
  4. 在 METHOD_PARAMETER_SCHEMAS 增加全部可编辑字段，写清中文含义、边界与默认值。
  5. 如果需要新组件名，注册 ComponentRegistry 工厂；如果新 loss weighting，同步 _loss_composer。
  6. 补 configs/methods 对应文件和 docs/method_catalog.yaml/方法页；Sphinx 展示及元数据要一致。
  7. 测参数未知键、类型、极值、组合冲突、短跑、状态保存与公平基线比较。

19.2 新几何

至少实现 dim、bounds、contains、sample_interior、sample_boundary；按用途增加 on_boundary/boundary_normal。接入 PDEProblem 允许类型、Experiment 评估采样、边界法向、前端生成代码。先用纯几何测试确认面积/采样域内性、边界命中、法向方向和退化参数，再训练最简单已知解。

步骤 E：不训练也能检查法向符号

import torch
import openpinn as op

space = op.RectangleWithCircularHoles(
    (0, 0), (40, 40), ((10, 20, 4), (30, 20, 4)),
    stratified_boundary=True,
)
point = torch.tensor([[14., 20.]], dtype=torch.float64)
# 孔洞 1 的最右侧，计算域外法向朝孔心，即 (-1, 0)。
torch.testing.assert_close(space.boundary_normal(point), point.new_tensor([[-1., 0.]]))

class Quadratic(torch.nn.Module):
    def forward(self, x):
        return (x - x.new_tensor((10, 20))).square().sum(dim=1, keepdim=True)

# u=16，du/dn=-8；2u+0.5du/dn=28。
bc = op.RobinBC(28, space.boundary_normal, alpha=2, beta=0.5)
torch.testing.assert_close(bc.error(Quadratic(), point), point.new_zeros((1, 1)))
points = space.boundary(6, seed=0, dtype=torch.float64)
assert space.on_boundary(points, atol=1e-8).all()
print("解析圆孔法向与 Robin 符号核对通过")

示例用 float64 和显式绝对容差检查圆周点，避免把浮点舍入误差当作不在边界。float32 或更大坐标量级应单独设定并验证容差，不能无限调大以掩盖错误。完成标准：以上自动检查通过，另用真实浏览器核对孔编号、直径显示、缩放拖拽、错误回退，再保存生成脚本到 examples/ 并用小预算运行。后续若声称提高了精度，还需独立参考和收敛实验；这份开发案例不替代那些证据。

19.5 本案例的设计取舍与扩展边界

  • 参数几何优先：圆孔训练使用解析圆心和半径，预览点列仍服务于编辑和编号，避免把显示分辨率当作训练几何精度。
  • 保守分流：只接受四顶点轴对齐矩形＋全部圆孔；不偷偷重排或修整任意 CAD 外框。任意外轮廓＋圆孔仍需后续明确设计混合几何接口。
  • 条件索引稳定：现有实现按 ring/edge 索引保留状态。未来增加插入/删除/重排时必须定义映射规则，不能假定当前 reconcile 会按空间自动匹配。
  • 采样兼容：stratified_boundary 默认为 False，生成器解析导入路径显式启用 True；该路径样本数至少覆盖四边和各孔。改变默认值要评估旧调用的随机采样与复现行为。
  • 阈值不是物理定律：拟圆容差改变需配套真圆、椭圆、噪声近圆和少边数多边形样例，记录误判/漏判；不能仅凭一个图片看起来更圆就调大容差。
