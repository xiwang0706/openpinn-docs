开始贡献：从反馈到开发计划

目标：把“感觉有问题 / 想加一个方法”变成别人能够复现和审阅的任务。 本页结束时应有最小输入、期望行为、修改范围、验收条件，以及可运行的开发环境。

开始贡献：把使用反馈变成可实施的任务

这份说明书不是另一份运行教程，也不要求你先理解所有算法。它帮助你把使用中发现的不足、研究中的新方法或一个小改进，变成其他人能运行、检查和维护的贡献。只想建模运行，请先读使用者说明书；想改变软件本身，从本节开始。

先判断是否需要改公共代码

  • 只想换 PDE、几何或参数：优先使用配置器、PDEProblem 或用户问题工厂。自己的实验不一定需要新增内置模型，见最小问题扩展。
  • 现有功能行为不正确：先提供最小复现和预期行为，再按修复路线定位。
  • 新增算法或公共能力：先说明现有扩展点为何不够、适用范围和验收标准，再按方法开发路线实施。
  • 文字、布局、报错提示不清楚：这是有效贡献，不必为了“小改动”引入新算法或重构整个配置器。

提交反馈或提案时，先让别人看见同一个问题

GitHub 仓库发布后，先查询是否已有同类 Issue；较大的新算法或破坏性接口变更，建议先提交提案并与维护者讨论。尚未发布时，可使用同样模板保存本地任务记录。不知道根因也可以报告问题，不要把猜测写成已经验证的事实。

任务类型：缺陷 / 新方法 / 新问题或几何 / 交互或文档
使用场景：为什么需要这个变化
当前行为：最小脚本、输入文件、复现步骤、完整错误
期望行为：应得到什么；什么不属于本次范围
基线：源码版本或哈希，OS，Python / PyTorch，涉及网页时记录浏览器
验收条件：可自动检查的结果 + 必须人工确认的内容
影响预判：公共 API、旧配置、检查点、文件格式、默认值是否改变
附件：可公开的最小输入；剔除个人路径、敏感图纸和无授权数据

新方法提案还应说明数学定义、论文/公式来源、适用问题、比较基线、计算预算和失败边界。论文有公式不意味着外部实现代码可直接复制；参考实现来源及其使用条件需要单独记录。

三条贡献路线

你的目标先做的最小成果实施入口完成时应能证明
增加算法、方法或变体确定算法所属组件和输入/输出/状态契约新增方法路线参数真正进入算法，旧路径仍可用；性能主张有独立证据
增加方程、几何或边界能力一个可计算残差、采样和条件误差的最小问题问题扩展、几何契约维度、单位、法向、导数与边界归属正确
修复缺陷、优化交互与文档一个稳定复现的输入和针对性回归修复路线原问题消失、相邻功能不回退，必要时预览和代码同步

第一次贡献的建议范围

优先选择能独立说明、独立验证的小任务，例如一个错误提示、一条参数校验或一个确定的编号错配。先在未修改版本上复现，保存基线，再在隔离分支或完整工作副本上修改。不要把“修复一个报错”与“重新组织全部训练模块”放在同一变更里。

下一步：按环境准备安装开发依赖，并按首次基线检查确认运行来源。开发期间按受影响层运行针对性测试，提交共享版本前按验证要求补齐证据。

01 · 维护范围、证据与阅读路线

先选贡献任务，再查实现细节。

从贡献计划确定范围，新增算法看方法路线，修复细节看维护路线。只有涉及自定义建模时，才需要同时核对表单状态、图中编号、生成代码和后端训练契约；不要求每项贡献都修改整条链路。

这份说明书面向接手当前 OpenPINN 的开发者。正文解释真实的控制流和模块契约，附录提供逐文件的类/函数定位与调用表达式。它描述当前实现，不将计划中的弱形式、任意 CAD 内核、多物理场图形编辑或在线训练写成已完成功能。

你要修改什么先读主要落点
新问题/PDE问题契约、边界、扩展实例user_projects、PDEProblem、benchmarks
新改进方法方法与组件配置、配置优先级、损失/采样/优化器methods、method_options、method_registry、对应公共组件
网页字段/几何编辑前端事件与生成代码链、图片/DXF 管线docs/_ext 与 docs/_static
指标/输出图评价、产物与参考数据链experiment、metrics、reference_data、artifacts
多人协作发布测试分层、协作变更矩阵、文档构建tests、configs、docs、scripts

事实来源是当前本地源码、配置、已有测试与页面生成逻辑。附录中的源码 docstring 保留原文；历史注释可能比实现窄，若与可执行实现冲突，应以具体函数体与测试为准。手册中的协作流程明确属于建议约定，不是已经存在的 CI/分支保护制度。

版本快照：目录名 v0.6-dev；包元数据、__version__ 和 Sphinx release 均为 0.2.0。交付时同时记录源码哈希，不能只报“0.2.0”。本次手册维护没有建立新的 Git 仓库或修改训练算法。

1.1 新成员首次接手：先建立可重复的工作环境

以下命令均在包含 pyproject.toml 的项目根目录执行。首次安装需要获取依赖；完成构建后的 HTML 阅读不需要 Node、Python 或联网。Node/jsdom 仅用于开发测试，不会被上传或打包进网页。使用项目内的依赖，不复制其他维护者的 .venv、node_modules 或临时目录。

Python 的声明下限见 pyproject.toml；Node/jsdom 以本项目锁文件为准。本次接手流程使用 Node 24.18.0、npm 11.16.0 和 jsdom 30.1.2 验证，这不是所有旧 Node 版本都受支持的承诺。出现 npm 的 engine 警告应先核对运行时，不要强行忽略。Python 依赖目前声明版本范围，尚未形成跨平台完整锁定环境；记录实际安装版本，不宣称跨机器逐位一致。

macOS / Linux

python -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[test,docs]"
node --version
npm --version
npm ci --ignore-scripts --no-audit --no-fund
node -e "console.log(require.resolve('jsdom'))"
python -c "import openpinn; print(openpinn.__version__); print(openpinn.__file__)"
python -m openpinn list-methods

Windows PowerShell

py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[test,docs]"
node --version
npm --version
npm ci --ignore-scripts --no-audit --no-fund
node -e "console.log(require.resolve('jsdom'))"
.\.venv\Scripts\python.exe -c "import openpinn; print(openpinn.__version__); print(openpinn.__file__)"
.\.venv\Scripts\python.exe -m openpinn list-methods

预期：OpenPINN 路径指向当前工作副本的 src/openpinn/__init__.py，jsdom 路径位于当前项目 node_modules。如果指向旧安装或临时目录，先处理解释器/环境变量再开始修改。Windows 下本章后续所有 python 可替换为上述虚拟环境解释器路径，不要求改变系统脚本执行策略。

1.2 第一次基线验证：构建在前，网页测试在后

python scripts/build_docs.py
node -e "require('jsdom'); console.log('DOM dependency ready')"
npm test
python -m pytest -q -ra
python -m pip freeze

第一条命令依次生成双说明书、验证标记的短示例、强制构建 Sphinx，最后打包说明书。Node 测试会读取构建后的 HTML，因此不能在干净工作副本上先执行 npm test。-ra 展示跳过等摘要；若生成器 smoke 因 Node/jsdom 缺失而跳过，不能签署“前端到训练链路已通过”。手册验证的通过也不能替代完整测试。

接手检查通过标准失败时先查
运行来源Python 与 jsdom 均解析到本项目虚拟环境、旧 wheel、NODE_PATH
构建入口退出码 0，网站内两份手册存在，validation 状态 passed开发依赖、Node 可执行文件、Sphinx 警告
自动回归npm test 与 pytest 通过；每个 skip 有原因和处理决定未构建 HTML、缺失样例/依赖、环境差异
人工预览打开 method_configurator.html，切换自定义几何、修改边界、观察代码同步是否打开旧 dist 页面、缓存、浏览器控制台
基线记录记录源码快照、OS、Python/Node/npm/依赖版本、命令和结果不得只记录“本地正常”或复制旧通过数量

先保存未修改版本的基线结果，再提交自己的变更。遇到已有失败应标明复现条件，不能把它静默归为本次新错误，也不能借机删除测试。

02 · 代码目录与单一可信来源

项目根目录
├── src/openpinn/            当前执行库：数值组件、组装、API
│   └── methods/             方法家族/变体元数据与配置补丁
├── configs/
│   ├── experiments/         短入口实验配置
│   ├── reference_runs/      底层展开式配置/比较基准
│   ├── problems/            问题配置片段
│   ├── methods/             方法默认配置片段
│   └── training/            训练配置片段
├── examples/               可运行示例、比较/复现驱动
│   └── geometries/          图形交换测试样例
├── user_projects/          用户问题工厂与运行文件
├── tests/                  unit / contract / smoke / regression / methods / js
├── docs/
│   ├── _ext/               Sphinx 扩展：构建配置器 HTML / payload
│   ├── _static/            前端 JS/CSS、几何导入与预览
│   ├── _build/html/        构建产物，不是维护源
│   └── manuals/            双说明书正文源与独立 HTML
├── scripts/                配置器验证、DXF 样例、手册构建
├── runs/                   实验输出，不自动充当通过验证的基准
├── results/                已保留的比较/验证产物
├── build/、dist/            历史构建/分发副本，可能落后于 src
└── pyproject.toml          安装元数据、依赖与入口

维护原则：库代码改 src/openpinn，网页结构改 docs/_ext/openpinn_method_catalog.py，行为改 docs/_static/*.js，不要只改 build/lib、dist 或 docs/_build。可编辑安装后通过 openpinn.__file__ 验证使用路径。

configs 目录不是自动扫描执行的插件目录。新放一个 YAML 并不会自动注册方法；方法短入口实际使用 Python registry/spec/schema。YAML 配置片段、文档目录和 Python 默认值需要维护者保持一致。
